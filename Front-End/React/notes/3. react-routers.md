
# React Interview Notes — 3. React Router

> **Package:** `react-router-dom` for React web applications.

---

# 1. What Is React Router?

React Router is a routing library for React applications.

It allows an application to display different UI based on the URL without requiring a full browser page reload for normal client-side navigation.

Example:

```text
/              → Home
/about         → About
/products      → Products
/products/10   → Product 10
/users/25      → User 25
```

A router connects:

```text
URL
 ↓
Route matching
 ↓
React component
 ↓
UI
```

---

# 2. Install React Router

```bash
npm install react-router-dom
```

Modern React Router APIs may also be available through the `react-router` package depending on the project setup/version.

For a typical browser React application, `react-router-dom` is commonly used.

---

# 3. BrowserRouter

The traditional declarative approach uses:

```jsx
import {
  BrowserRouter,
  Routes,
  Route
} from "react-router-dom";
```

Example:

```jsx
function App() {
  return (
    <BrowserRouter>
      <Routes>
        <Route path="/" element={<Home />} />
        <Route path="/about" element={<About />} />
      </Routes>
    </BrowserRouter>
  );
}
```

---

# 4. `Routes` and `Route`

`Routes` contains route definitions.

```jsx
<Routes>
  <Route
    path="/"
    element={<Home />}
  />

  <Route
    path="/about"
    element={<About />}
  />
</Routes>
```

A `Route` maps:

```text
URL pattern → React element
```

Example:

```jsx
<Route
  path="/about"
  element={<About />}
/>
```

means:

```text
/about → <About />
```

---

# 5. `createBrowserRouter`

React Router also provides a data-router API:

```jsx
import {
  createBrowserRouter
} from "react-router-dom";
```

Example:

```jsx
const router = createBrowserRouter([
  {
    path: "/",
    element: <Home />
  },
  {
    path: "/about",
    element: <About />
  }
]);
```

Then:

```jsx
import {
  RouterProvider
} from "react-router-dom";

createRoot(
  document.getElementById("root")
).render(
  <RouterProvider router={router} />
);
```

# 6. `RouterProvider`

`RouterProvider` provides the router to the React application.

```jsx
import {
  createBrowserRouter,
  RouterProvider
} from "react-router-dom";

const router = createBrowserRouter([
  {
    path: "/",
    element: <Home />
  }
]);

createRoot(
  document.getElementById("root")
).render(
  <RouterProvider router={router} />
);
```

This replaces the simple:

```jsx
<App />
```

entry point when using the data-router configuration.

# 7. Nested Routes

Nested routes allow a parent route to render child routes.

Example:

```jsx
const router = createBrowserRouter([
  {
    path: "/",
    element: <Layout />,
    children: [
      {
        index: true,
        element: <Home />
      },
      {
        path: "about",
        element: <About />
      }
    ]
  }
]);
```

URL structure:

```text
/       → Layout + Home
/about  → Layout + About
```

---

# 8. `Outlet`

`Outlet` is the location where the matched child route is rendered.

```jsx
import {
  Outlet
} from "react-router-dom";

function Layout() {
  return (
    <>
      <Header />

      <main>
        <Outlet />
      </main>

      <Footer />
    </>
  );
}
```

Route configuration:

```jsx
const router = createBrowserRouter([
  {
    path: "/",
    element: <Layout />,
    children: [
      {
        index: true,
        element: <Home />
      },
      {
        path: "about",
        element: <About />
      }
    ]
  }
]);
```

Conceptually:

```text
Layout
├── Header
├── Outlet
│    ├── Home
│    └── About
└── Footer
```

---

# 9. Why Use `Outlet`?

Suppose Header and Footer should remain part of the layout:

```text
┌─────────────────────┐
│       Header        │
├─────────────────────┤
│                     │
│   Current Route     │
│                     │
├─────────────────────┤
│       Footer        │
└─────────────────────┘
```

The current child route appears inside:

```jsx
<Outlet />
```

This avoids duplicating the Header/Footer in every page component.

# 11. Dynamic Routes

A route parameter starts with `:`.

```jsx
{
  path: "users/:userId",
  element: <User />
}
```

Examples:

```text
/users/10
/users/25
/users/sagar
```

All match:

```text
/users/:userId
```

# 12. `useParams`

Read dynamic parameters using `useParams`.

```jsx
import {
  useParams
} from "react-router-dom";

function User() {
  const { userId } = useParams();

  return (
    <h1>
      User: {userId}
    </h1>
  );
}
```

For:

```text
/users/25
```

the value is:

```js
userId === "25"
```

### Important

Route parameters are strings.

If you need a number:

```jsx
const id = Number(userId);
```

# 15. Why Not Use `<a>` for Internal Routes?

This:

```html
<a href="/about">
  About
</a>
```

can cause a normal browser navigation.

For React Router navigation, prefer:

```jsx
<Link to="/about">
  About
</Link>
```

React Router can handle the client-side navigation without requiring a full page reload.

### Important

Use regular `<a>` when linking to an external website:

```jsx
<a
  href="https://example.com"
  target="_blank"
  rel="noreferrer"
>
  External Website
</a>
```

# 17. Active Class with `NavLink`

`className` can receive an object describing the current link state.

```jsx

  className={({ isActive }) =>
    isActive
      ? "active"
      : "inactive"

</NavLink>
```

More practical:

```jsx

  to="/about"
  className={({ isActive }) =>

        ? "active"
        : ""
    }`
  }
>
  About
</NavLink>
```

# 20. Replace Current History Entry

```jsx
navigate("/login", {
  replace: true
});
```

This replaces the current history entry instead of adding a new one.

Common use case:

```text
User visits protected page
        ↓
Not authenticated
        ↓
Redirect to login
        ↓
replace: true
```

This can prevent the protected page from remaining as the immediately previous history entry.

# 23. Query Parameters

Query parameters appear after `?`.

Example:

```text
/products?category=phone&page=2
```

Use `useSearchParams`:

```jsx
import {
  useSearchParams
} from "react-router-dom";

function Products() {
  const [
    searchParams,
    setSearchParams
  ] = useSearchParams();

  const category =
    searchParams.get("category");

  const page =
    searchParams.get("page");

  return (
    <div>
      <p>Category: {category}</p>
      <p>Page: {page}</p>
    </div>
  );
}
```

For:

```text
/products?category=phone&page=2
```

result:

```text
category → "phone"
page     → "2"
```

---

# 24. Updating Search Params

```jsx
setSearchParams({
  category: "laptop",

});
```

Example:

```jsx
function Filters() {
  const [
    searchParams,
    setSearchParams
  ] = useSearchParams();

  function showLaptops() {
    setSearchParams({
      category: "laptop",
      page: "1"

  return (
    <button onClick={showLaptops}>

    </button>

```

# 25. Path Params vs Query Params

### Path parameter

```text
/users/25
```

Route:

```jsx
/users/:userId
```

Used when the value identifies a resource.

### Query parameter

```text
/users?role=admin&page=2
```

Used commonly for:

* Filtering
* Searching
* Sorting
* Pagination
* Optional parameters

---

# 26. Route Params vs Query Params

| Path Params                 | Query Params                    |
| --------------------------- | ------------------------------- |
| `/users/:id`                | `/users?id=10`                  |
| Part of route path          | After `?`                       |
| Usually identifies resource | Usually filters/configures view |
| Read with `useParams()`     | Read with `useSearchParams()`   |

# 30. Route Loader

Data routers support route loaders.

Example:

```jsx
const router =
  createBrowserRouter([
    {
      path: "/github",
      element: <Github />,
      loader: githubLoader
    }
  ]);
```

Loader:

```jsx
async function githubLoader() {
  const response = await fetch(
    "https://api.github.com/users/octocat"
  );

  if (!response.ok) {
    throw new Error(
      "Failed to load GitHub user"
    );
  }

  return response.json();
}
```

---

# 31. `useLoaderData`

The route component can access the loader result:

```jsx
import {
  useLoaderData
} from "react-router-dom";

function Github() {
  const data = useLoaderData();

  return (
    <div>
      <h1>{data.name}</h1>
      <p>
        Followers: {data.followers}
      </p>
    </div>
  );
}
```

Flow:

```text
Route
  ↓
loader()
  ↓
fetch data
  ↓
Route renders
  ↓
useLoaderData()
```

---

# 32. Why Use a Loader?

A loader associates data loading with a route.

Instead of:

```text
Component mounts
   ↓
useEffect()
   ↓
fetch()
   ↓
setState()
   ↓
render data
```

a data router can load route data as part of navigation.

This can simplify route-level data loading and gives React Router control over navigation/data lifecycle.

---

# 33. Loader Error Handling

A loader should check failed HTTP responses because `fetch()` does not reject automatically for HTTP errors such as 404 or 500.

```jsx
async function loader() {
  const response = await fetch("/api/users");

  if (!response.ok) {
    throw new Response(
      "Failed to load users",
      {
        status: response.status
      }
    );
  }

  return response.json();
}
```

Modern applications may instead throw an `Error` or use the routing APIs appropriate to their version.

# 35. Protected Routes

A common pattern is protecting routes based on authentication.

Example:

```jsx
import {
  Navigate,
  Outlet
} from "react-router-dom";

function ProtectedRoute({
  isAuthenticated
}) {
  if (!isAuthenticated) {
    return (
      <Navigate
        to="/login"
        replace
      />
    );
  }

  return <Outlet />;
}
```

Router:

```jsx
const router =
  createBrowserRouter([
    {
      path: "/",
      element: <RootLayout />,
      children: [
        {
          path: "login",
          element: <Login />
        },
        {
          element: (
            <ProtectedRoute
              isAuthenticated={isAuthenticated}
            />
          ),
          children: [
            {
              path: "dashboard",
              element: <Dashboard />
            },
            {
              path: "profile",
              element: <Profile />
            }
          ]
        }
      ]
    }
  ]);
```

Concept:

```text
/dashboard
     ↓
ProtectedRoute
     ↓
Authenticated?
   ↙       ↘
 yes       no
 ↓          ↓
Outlet    /login
```

# 40. Lazy Loading Routes

Large applications can lazy-load route components.

```jsx
import {
  lazy,
  Suspense
} from "react";

const Dashboard = lazy(
  () => import("./pages/Dashboard")
);

function App() {
  return (
    <Suspense fallback={<p>Loading...</p>}>
      <Dashboard />
    </Suspense>
  );
}
```

This can reduce the initial JavaScript needed by the browser.

Route-level lazy loading can also be configured using React Router's route APIs.

# 44. `action`

React Router data routers also support route actions for mutations such as form submissions.

Example:

```jsx
const router =
  createBrowserRouter([
    {
      path: "/login",
      element: <Login />,
      action: loginAction
    }
  ]);
```

Action:

```jsx
async function loginAction({
  request
}) {
  const formData =
    await request.formData();

  const username =
    formData.get("username");

  // Perform login operation.

  return {
    success: true,
    username
  };
}
```

The action is associated with a route and is designed for route-driven mutations.

# 45. `Form`

React Router provides a `Form` component for data-router forms.

```jsx
import {

} from "react-router-dom";

function Login() {
  return (

        name="username"
        required
      />

        name="password"
        type="password"

      />

      </button>
```

The submission can be handled by the route's `action`.

# 46. Router Data Flow

With a data router:

```text
Navigation
    ↓
Route matching
    ↓
loader()
    ↓
Data available
    ↓
Route component
    ↓
useLoaderData()
```

For mutation:

```text
Form submission
      ↓
route action()
      ↓
mutation
      ↓
navigation/revalidation
      ↓
updated loader data
```

# 47. Common React Router Interview Questions

## What is React Router?

> A routing library/ecosystem for React applications that maps URLs to UI and supports client-side navigation and, with data routers, route-level data loading and mutations.

---

## What is `Outlet`?

> `Outlet` is the placeholder where the currently matched child route renders inside a parent route.

---

## What is `useParams`?

> A Hook that reads dynamic URL parameters defined with `:` in a route path.

Example:

```jsx
<Route
  path="/users/:id"
  element={<User />}
/>
```

```jsx
const { id } = useParams();
```

---

## What is `Link`?

> A React Router component used for client-side navigation between routes.

---

## `Link` vs `<a>`

```text
Link
→ React Router navigation

<a>
→ Browser navigation
```

For internal SPA routes, use `Link`/`NavLink`.

For external URLs, use `<a>`.

---

## `useNavigate` vs `Link`

```text
Link
→ user-driven navigation UI

useNavigate
→ programmatic navigation
```

---

## What is `NavLink`?

> A navigation link that provides information about whether the link matches the current route, making active styling easier.

---

## What is a dynamic route?

```jsx
<Route
  path="/users/:userId"
  element={<User />}
/>
```

`:userId` is a dynamic parameter.

---

## What is a nested route?

A route defined as a child of another route.

```jsx
{
  path: "/",
  element: <Layout />,
  children: [
    {
      path: "about",
      element: <About />
    }
  ]
}
```

---

## What is a loader?

> A route-level data-loading function supported by React Router's data APIs.

---

## What is `useLoaderData`?

> A Hook that reads data returned by the matched route's loader.

---

# 48. Common Mistakes

### ❌ Incorrect

```jsx
<Route
  path="/users/:id"
  element={User}
/>
```

### ✅ Correct

```jsx
<Route
  path="/users/:id"
  element={<User />}
/>
```

---

### ❌ Incorrect

```jsx
<Link href="/about">
  About
</Link>
```

### ✅ Correct

```jsx
<Link to="/about">
  About
</Link>
```

`Link` uses `to`, not `href`.

---

### ❌ Incorrect

```jsx
<NavLink
  className={isActive ? "active" : ""}
>
```

### ✅ Correct

```jsx
<NavLink
  to="/about"
  className={({ isActive }) =>
    isActive ? "active" : ""
  }
/>
```

---

### ❌ Incorrect

```jsx
{
  path: "",
  element: <Home />
}
```

for a route where you specifically mean the parent's index route.

### ✅ Prefer

```jsx
{
  index: true,
  element: <Home />
}
```

---

### ❌ Incorrect

```jsx
function Layout() {
  return (
    <>
      <Header />
      <Home />
      <Footer />
    </>
  );
}
```

if the intention is to render different nested route pages.

### ✅ Correct

```jsx
function Layout() {
  return (
    <>
      <Header />
      <Outlet />
      <Footer />
    </>
  );
}
```

# 54. High-Value Interview Answers

### How does nested routing work?

> A parent route defines child routes, and the parent component renders an `Outlet`. React Router renders the matched child route at that `Outlet`.

### How do you get an ID from `/users/123`?

```jsx
const { id } = useParams();
```

with:

```jsx
<Route
  path="/users/:id"
  element={<User />}
/>
```

### How do you navigate after login?

```jsx
const navigate = useNavigate();

navigate("/dashboard", {
  replace: true
});
```

### How do you highlight the active navigation link?

Use `NavLink`:

```jsx
<NavLink
  to="/about"
  className={({ isActive }) =>
    isActive ? "active" : ""
  }
/>
```

### How do you render a child route inside a layout?

Use:

```jsx
<Outlet />
```

### How do you read `?page=2`?

```jsx
const [
  searchParams
] = useSearchParams();

const page =
  searchParams.get("page");
```

### How do you load data for a route?

With a data router:

```jsx
{
  path: "/users",
  loader: usersLoader,
  element: <Users />
}
```

and:

```jsx
const users =
  useLoaderData();
```

# 55. Important Interview Correction

Avoid describing React Router simply as:

> "It changes components without refreshing the page."

That is incomplete.

A stronger answer:

> React Router matches the current URL against a route configuration and renders the corresponding route elements. Its navigation APIs can update the URL and UI through client-side navigation, while data routers additionally coordinate route-level loading, mutations, and error handling.
