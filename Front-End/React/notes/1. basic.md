# React Interview Notes — 1. React Basics

> **Current reference:** React 19.3.
> These notes focus on React fundamentals. Hooks, Router, Context API, Redux/RTK, and advanced topics are covered separately.

---

## 1. What is React?

**React** is a JavaScript library for building user interfaces, especially component-based web applications.

Key ideas:

* Component-based architecture
* Declarative UI
* Reusable components
* One-way data flow
* State-driven rendering
* JSX
* Hooks
* Virtual DOM / React reconciliation
* Ecosystem support for routing, state management, forms, data fetching, etc.

React itself is primarily the UI library.

### React vs React DOM vs React Native

| Package            | Purpose                                               |
| ------------------ | ----------------------------------------------------- |
| `react`            | Core React APIs: components, hooks, JSX runtime, etc. |
| `react-dom`        | React integration with the browser DOM                |
| `react-native`     | Build native mobile applications using React          |
| `react-router-dom` | Routing for React web applications                    |
| `react-redux`      | React bindings for Redux                              |

For a web application, commonly:

```bash
npm install react react-dom
```

For React Native:

```bash
npm install react react-native
```

> React Native is not simply "React for mobile browsers"; it renders native UI components.


# 6. React Entry Point

A typical Vite React application has:

```jsx

import { createRoot } from "react-dom/client";
import App from "./App.jsx";

createRoot(document.getElementById("root")).render(
  <StrictMode>
    <App />
  </StrictMode>
);
```

And:

```html
<!-- index.html -->

<div id="root"></div>
```

### Flow

```text
index.html
    ↓
<div id="root">
    ↓
main.jsx
    ↓
createRoot(...)
    ↓
<App />
    ↓
React component tree
```

# 7. `createRoot()`

Modern React applications use:

```jsx
import { createRoot } from "react-dom/client";

const root = createRoot(document.getElementById("root"));

root.render(<App />);
```

`createRoot()` creates a React root attached to a DOM element.

### Older React

Older React versions commonly used:

```jsx
ReactDOM.render(<App />, document.getElementById("root"));
```

For modern React applications, use:

```jsx
createRoot(...)
```

---

# 8. StrictMode

`StrictMode` is a development-only tool that helps detect common problems.

```jsx
import { StrictMode } from "react";

createRoot(document.getElementById("root")).render(
  <StrictMode>
    <App />
  </StrictMode>
);
```

Important:

* It does **not** render your production application twice.
* It enables additional development checks.
* In development, React may intentionally re-render components or re-run Effects to expose bugs.
* This can make `console.log()` appear more than once during development.

Example:

```jsx
function App() {
  console.log("App rendered");

  return <h1>Hello React</h1>;
}
```

With `StrictMode`, you may see the log twice in development.

Do not "fix" this by removing `StrictMode` unless you have a specific reason.

# 9. Components

A React application is composed of components.

A component is usually a JavaScript function that returns React elements.

```jsx
function Welcome() {
  return <h1>Hello React</h1>;
}
```

Use it:

```jsx
function App() {
  return (
    <div>
      <Welcome />
    </div>
  );
}
```

### Component naming rule

Custom React components should start with an uppercase letter:

```jsx
<User />
```

HTML elements use lowercase:

```jsx
<div />
<button />
```

This distinction tells React whether something is a built-in HTML element or a user-defined component.

---

# 10. Component Example

```jsx
function Header() {
  return <header>My Website</header>;
}

function Footer() {
  return <footer>Copyright 2026</footer>;
}

function App() {
  return (
    <>
      <Header />

      <main>
        <h1>Welcome</h1>
      </main>

      <Footer />
    </>
  );
}

export default App;
```

React components can be nested:

```text
App
├── Header
├── Main
└── Footer
```

This creates a component tree.

# 11. JSX

JSX is a syntax extension for JavaScript that lets you write markup-like syntax inside JavaScript.

Example:

```jsx
const element = (
  <h1 className="greeting">
    Hello, world!
  </h1>
);
```

JSX is **not HTML**.

It looks similar to HTML but follows JavaScript/JSX rules.

---

# 12. JSX Rules

## Close tags

HTML:

```html
<input>
```

JSX:

```jsx
<input />
```

Both opening and closing tags must be properly formed.

```jsx
<div>
  <span>Hello</span>
</div>
```

---

## `className` instead of `class`

HTML:

```html
<div class="container"></div>
```

JSX:

```jsx
<div className="container"></div>
```

---

## JavaScript expressions use `{}`

```jsx
const username = "Sagar";

function App() {
  return <h1>Hello {username}</h1>;
}
```

Output:

```text
Hello Sagar
```

---

## Expressions inside JSX

You can use JavaScript expressions:

```jsx
const name = "Sagar";
const age = 25;

return (
  <div>
    <h1>{name}</h1>
    <p>Age: {age}</p>
    <p>{age >= 18 ? "Adult" : "Minor"}</p>
  </div>
);
```

You cannot directly put arbitrary statements inside JSX:

```jsx
// ❌ Not valid JSX
<div>
  {if (isLoggedIn) {
    "Welcome";
  }}
</div>
```

Use JavaScript control flow outside JSX or an expression such as:

```jsx
{isLoggedIn && <p>Welcome</p>}
```

---

# 13. JSX Transformation

Conceptually, JSX:

```jsx
const element = (
  <h1 className="greeting">
    Hello, world!
  </h1>
);
```

is transformed by the JSX toolchain into React element creation code.

Historically, this was commonly represented as:

```jsx
React.createElement(
  "h1",
  { className: "greeting" },
  "Hello, world!"
);
```

Modern React projects generally use the **automatic JSX transform**, so you often do not need:

```jsx
import React from "react";
```

just to use JSX.

# 14. Fragment

A React component can return multiple sibling elements by wrapping them in a Fragment.

Short syntax:

```jsx
function App() {
  return (
    <>
      <h1>Hello</h1>
      <p>Welcome</p>
    </>
  );
}
```

Equivalent explicit syntax:

```jsx
import { Fragment } from "react";

function App() {
  return (
    <Fragment>
      <h1>Hello</h1>
      <p>Welcome</p>
    </Fragment>
  );
}
```

A Fragment groups elements **without adding an extra DOM element**.

Instead of:

```jsx
<div>
  <h1>Hello</h1>
  <p>Welcome</p>
</div>
```

you can use:

```jsx
<>
  <h1>Hello</h1>
  <p>Welcome</p>
</>
```

### Interview point

A Fragment is useful when you need a common React parent but don't want an unnecessary DOM node.

# 15. Props

**Props = properties passed from a parent component to a child component.**

Props are used to make components reusable.

Example:

```jsx
function Card({ username }) {
  return <h2>Hello {username}</h2>;
}
```

Parent:

```jsx
function App() {
  return (
    <>
      <Card username="Sagar" />
      <Card username="Rahul" />
    </>
  );
}
```

The same component can display different data.

---

# 16. Passing Props

String:

```jsx
<Card username="Sagar" />
```

Number:

```jsx
<Card age={25} />
```

Boolean:

```jsx
<Card isAdmin={true} />
```

Object:

```jsx
<Card user={{ name: "Sagar", age: 25 }} />
```

Array:

```jsx
<Card skills={["React", "JavaScript", "CSS"]} />
```

Function:

```jsx
<Card onDelete={handleDelete} />
```

---

# 17. Receiving Props

Using the `props` object:

```jsx
function Card(props) {
  return <h1>{props.username}</h1>;
}
```

Using destructuring:

```jsx
function Card({ username }) {
  return <h1>{username}</h1>;
}
```

Both are valid.

---

# 18. Props Are Read-Only

A child should not modify its props.

```jsx
function User({ name }) {
  // ❌ Do not do this
  name = "Rahul";

  return <h1>{name}</h1>;
}
```

Props are inputs to a component.

If a component needs to change something over time, that changing value normally belongs in **state**.

---

# 19. Props Are One-Way

Data normally flows:

```text
Parent
   ↓
Child
```

Example:

```jsx
function Parent() {
  const username = "Sagar";

  return <Child username={username} />;
}

function Child({ username }) {
  return <h1>{username}</h1>;
}
```

A child cannot directly modify the parent's state.

For child-to-parent communication, the parent can pass a callback:

```jsx
function Parent() {
  const handleMessage = (message) => {
    console.log(message);
  };

  return <Child onMessage={handleMessage} />;
}

function Child({ onMessage }) {
  return (
    <button onClick={() => onMessage("Hello Parent")}>
      Send
    </button>
  );
}
```

Data flow is still controlled by the parent:

```text
Parent
  │
  ├── data ───────────────→ Child
  │
  └── callback function ──→ Child
                              │
                              └── calls callback
                                      ↓
                                    Parent
```

# 20. `children` Prop

Anything placed between a component's opening and closing tags is available through the `children` prop.

```jsx
function Card({ children }) {
  return (
    <div className="card">
      {children}
    </div>
  );
}
```

Usage:

```jsx
<Card>
  <h2>Hello</h2>
  <p>This is inside the card.</p>
</Card>
```

`children` is especially useful for reusable layout components.

# 21. Event Handling

React uses event props such as:

```jsx
onClick
onChange
onSubmit
onMouseEnter
onKeyDown
```

Example:

```jsx
function App() {
  const handleClick = () => {
    console.log("Button clicked");
  };

  return (
    <button onClick={handleClick}>
      Click Me
    </button>
  );
}
```

### Important

Pass the function:

```jsx
onClick={handleClick}
```

Do not call it during rendering:

```jsx
// ❌ Wrong
onClick={handleClick()}
```

If arguments are required:

```jsx
<button onClick={() => handleDelete(10)}>
  Delete
</button>
```

---

# 22. Event Object

React passes an event object to event handlers.

```jsx
function App() {
  const handleChange = (event) => {
    console.log(event.target.value);
  };

  return (
    <input onChange={handleChange} />
  );
}
```

For forms:

```jsx
function App() {
  const handleSubmit = (event) => {
    event.preventDefault();

    console.log("Form submitted");
  };

  return (
    <form onSubmit={handleSubmit}>
      <button type="submit">
        Submit
      </button>
    </form>
  );
}
```

# 23. State

**State is data managed by a component that can change over time.**

When state changes, React schedules a re-render of the component.

Basic example:

```jsx
import { useState } from "react";

function Counter() {
  const [count, setCount] = useState(0);

  return (
    <div>
      <h1>{count}</h1>

      <button onClick={() => setCount(count + 1)}>
        +
      </button>
    </div>
  );
}
```

`useState()` returns:

```text
[state, setter]
```

Example:

```jsx
const [count, setCount] = useState(0);
```

Where:

```text
count      → current state value
setCount   → function used to update state
0          → initial state
```

A detailed discussion of Hooks is kept in the Hooks notes.

---

# 24. State Must Not Be Mutated Directly

For primitive state:

```jsx
const [count, setCount] = useState(0);
```

Use:

```jsx
setCount(count + 1);
```

Not:

```jsx
// ❌
count = count + 1;
```

For objects:

```jsx
const [user, setUser] = useState({
  name: "Sagar",
  age: 25
});
```

Update immutably:

```jsx
setUser({
  ...user,
  age: 26
});
```

For arrays:

```jsx
const [items, setItems] = useState([]);
```

Add:

```jsx
setItems([...items, newItem]);
```

Remove:

```jsx
setItems(items.filter(item => item.id !== id));
```

Do not mutate the existing state object/array directly.

---

# 25. Functional State Updates

When the next state depends on the previous state, prefer the functional form:

```jsx
setCount(prevCount => prevCount + 1);
```

This is especially important when multiple updates are queued.

Example:

```jsx
setCount(prev => prev + 1);
setCount(prev => prev + 1);
setCount(prev => prev + 1);
```

This correctly represents three increments.

---

# 26. Rendering

React components should be treated as pure functions of their inputs:

```text
UI = f(props, state, context)
```

Given the same inputs, rendering should produce the same result.

Avoid side effects during render.

### Bad

```jsx
function Component() {
  localStorage.setItem("name", "Sagar");

  return <h1>Hello</h1>;
}
```

Side effects should be performed through the appropriate mechanism, such as event handlers or Effects depending on the use case.

---

# 27. Re-render

A re-render means React calls a component again to determine what the UI should look like.

A component may re-render when, for example:

* Its state changes.
* Its parent re-renders.
* Its context value changes.
* A subscribed external store changes.

A re-render does **not** necessarily mean the entire DOM is recreated.

React compares the rendered result and applies the necessary DOM updates.

---

# 28. React Rendering Mental Model

A useful interview model:

```text
State / Props / Context change
            ↓
       React renders
            ↓
  New React element tree
            ↓
       Reconciliation
            ↓
  Necessary DOM updates
```

Do not describe React as simply:

> "React changes the whole Virtual DOM every time."

That is an oversimplification.

---

# 29. Virtual DOM

The Virtual DOM is a useful conceptual model for React's in-memory representation of UI.

Instead of manually updating the DOM:

```js
document.querySelector(...).textContent = ...
```

you describe the desired UI:

```jsx
<h1>{count}</h1>
```

React determines what changes are needed.

### Important interview distinction

```text
Virtual DOM ≠ actual browser DOM
```

React maintains an internal representation of the rendered UI and uses reconciliation to determine updates.

---

# 30. Reconciliation

**Reconciliation** is the process React uses to determine what changed between renders and what needs to be updated.

Example:

Initial:

```jsx
<h1>Count: 0</h1>
```

Next render:

```jsx
<h1>Count: 1</h1>
```

React can determine that the text content changed rather than recreating the entire page.

---

# 31. React Fiber

**Fiber** is the internal architecture React uses to represent and process work.

Fiber enables React to:

* Break rendering work into units.
* Prioritize work.
* Schedule work.
* Pause/resume/discard work where appropriate.
* Support concurrent rendering capabilities.

### Interview distinction

```text
Virtual DOM
    ↓
Conceptual representation of UI

Fiber
    ↓
React's internal architecture for processing rendering work
```

Do not say:

> "Fiber is the Virtual DOM."

They are related concepts but not the same thing.

---

# 32. Conditional Rendering

React uses normal JavaScript for conditional rendering.

## `if`

```jsx
function Greeting({ isLoggedIn }) {
  if (isLoggedIn) {
    return <h1>Welcome!</h1>;
  }

  return <h1>Please log in.</h1>;
}
```

---

## Ternary

```jsx
return (
  <div>
    {isLoggedIn ? <Dashboard /> : <Login />}
  </div>
);
```

---

## Logical AND

```jsx
return (
  <div>
    {isLoggedIn && <p>Welcome!</p>}
  </div>
);
```

### Important `&&` pitfall

This:

```jsx
{count && <p>Count exists</p>}
```

can render `0` when `count` is `0`.

Safer:

```jsx
{count > 0 && <p>Count exists</p>}
```

---

# 33. Rendering Lists

Use JavaScript's `map()`:

```jsx
const users = [
  { id: 1, name: "Sagar" },
  { id: 2, name: "Rahul" },
  { id: 3, name: "Amit" }
];

function UserList() {
  return (
    <ul>
      {users.map(user => (
        <li key={user.id}>
          {user.name}
        </li>
      ))}
    </ul>
  );
}
```

---

# 34. Keys

Keys help React identify list items between renders.

```jsx
{users.map(user => (
  <User key={user.id} user={user} />
))}
```

A good key should be:

* Unique among siblings.
* Stable.
* Associated with the item itself.

Prefer:

```jsx
key={user.id}
```

Avoid:

```jsx
key={Math.random()}
```

Avoid array indexes when the list can be reordered, inserted into, or deleted from:

```jsx
key={index}
```

An index can be acceptable when the list is static and never reordered/inserted/deleted.

### Important

`key` is used by React and is **not automatically passed as a normal prop**.

This does not work:

```jsx
function User({ key }) {
  // key is not available as a normal prop
}
```

If the component needs the ID, pass it separately:

```jsx
<User
  key={user.id}
  id={user.id}
  user={user}
/>
```

# 35. Controlled Input

A controlled input gets its value from React state.

```jsx
import { useState } from "react";

function Form() {
  const [name, setName] = useState("");

  return (
    <input
      value={name}
      onChange={event => setName(event.target.value)}
    />
  );
}
```

Data flow:

```text
React state
    ↓
input value
    ↓
User types
    ↓
onChange
    ↓
setState
    ↓
React re-renders
    ↓
input value updated
```

---

# 36. Uncontrolled Input

An uncontrolled input keeps its current value in the DOM rather than React state.

A ref can be used to access it:

```jsx
import { useRef } from "react";

function Form() {
  const inputRef = useRef(null);

  const handleSubmit = event => {
    event.preventDefault();

    console.log(inputRef.current.value);
  };

  return (
    <form onSubmit={handleSubmit}>
      <input ref={inputRef} />

      <button type="submit">
        Submit
      </button>
    </form>
  );
}
```

Controlled vs uncontrolled inputs are an important interview topic.

---

# 37. Lifting State Up

When two or more components need to share the same state, move the state to their nearest common parent.

Before:

```text
Component A
    own state

Component B
    own state
```

If both need the same state:

```text
        Parent
          |
      shared state
       /       \
      A         B
```

Example:

```jsx
function Parent() {
  const [value, setValue] = useState("");

  return (
    <>
      <Input value={value} setValue={setValue} />
      <Display value={value} />
    </>
  );
}
```

This is called **lifting state up**.

---

# 38. Derived State

Do not store data in state if it can be calculated from existing state or props.

### Avoid unnecessary state

```jsx
const [firstName, setFirstName] = useState("Sagar");
const [lastName, setLastName] = useState("Patil");
const [fullName, setFullName] = useState("Sagar Patil");
```

`fullName` can be derived:

```jsx
const fullName = `${firstName} ${lastName}`;
```

This avoids having multiple sources of truth.

---

# 39. Single Source of Truth

For a piece of data, ideally maintain one authoritative source.

Bad:

```text
State A → username
State B → username
```

These can become inconsistent.

Better:

```text
One source
    ↓
username
    ↓
Components derive what they need
```

This principle becomes especially important when working with Context, Redux, Zustand, server state, forms, and derived data.

---

# 40. Component Composition

React encourages composing components instead of creating huge components.

Example:

```jsx
function App() {
  return (
    <Page>
      <Header />
      <Sidebar />
      <MainContent />
      <Footer />
    </Page>
  );
}
```

Each component can have a focused responsibility.

---

# 41. `children` and Composition

Composition allows reusable components to receive UI as children.

```jsx
function Modal({ children }) {
  return (
    <div className="modal">
      {children}
    </div>
  );
}
```

Usage:

```jsx
<Modal>
  <h2>Delete Account?</h2>
  <button>Delete</button>
</Modal>
```

This is often preferable to creating many components with numerous configuration props.

# 42. React and SPA

A **Single Page Application (SPA)** generally loads a single HTML document and updates the UI dynamically without full browser page reloads for normal client-side navigation.

Typical architecture:

```text
Browser
   ↓
index.html
   ↓
React application
   ↓
Components
   ↓
Client-side routing
   ↓
Different UI views
```

Important:

> SPA does not mean that the application must have exactly one HTML file in every deployment architecture.

Modern React applications can also use SSR, SSG, React Server Components, and frameworks that generate multiple HTML responses.

---

# 43. React Is Not a Complete Framework

React primarily focuses on UI.

A production application may additionally need:

```text
React
├── Routing
├── Data fetching
```

# 45. Important Interview Differences

## Props vs State

| Props                              | State                             |
| ---------------------------------- | --------------------------------- |
| Passed into component              | Managed by component              |
| Read-only from child's perspective | Updated using state setter/API    |
| Usually comes from parent          | Can be local or otherwise managed |
| Used to configure components       | Used for changing data            |
| Changes can cause re-render        | Changes cause re-render           |

---

## Component vs Element

### Component

A reusable piece of UI logic.

```jsx
function Button() {
  return <button>Click</button>;
}
```

### Element

A description of what should appear.

```jsx
<Button />
```

or:

```jsx
<button>Click</button>
```

---

## DOM vs Virtual DOM

```text
DOM
→ Browser's actual document structure

React's internal UI representation
→ Used by React during rendering/reconciliation
```

Do not claim React updates the entire browser DOM after every state change.

---

## State update vs direct mutation

Correct:

```jsx
setUser({
  ...user,
  name: "Rahul"
});
```

Incorrect:

```jsx
user.name = "Rahul";
```

# 46. Common Interview Traps

### ❌ "React is a framework."

Better:

> React is primarily a JavaScript library for building user interfaces.

---

### ❌ "Virtual DOM means React never touches the real DOM."

React ultimately updates the actual DOM in browser-based applications.

The point is that React determines the necessary updates rather than requiring developers to manually manipulate the DOM for normal UI updates.

---

### ❌ "Every state update immediately changes the DOM."

State updates schedule React work. React then renders/reconciles and commits the necessary updates.

---

### ❌ "Props can be modified by the child."

Props should be treated as immutable/read-only inputs.

---

### ❌ "The index is always a bad key."

Index keys are problematic when list items can change position, be inserted, or deleted. They can be acceptable for genuinely static lists.

---

### ❌ "JSX is HTML."

JSX is JavaScript syntax for describing UI. It resembles HTML but has different rules.

---

### ❌ "Fragment is a DOM element."

A Fragment groups React nodes without introducing an extra DOM element.

---

### ❌ "Re-render means the entire DOM is recreated."

A re-render means React evaluates the component tree again. React then determines the required DOM changes.

# 47. Basic React Example

```jsx
import { useState } from "react";

function UserCard({ name, age }) {
  return (
    <article>
      <h2>{name}</h2>
      <p>Age: {age}</p>
    </article>
  );
}

function App() {
  const [count, setCount] = useState(0);

  const users = [
    { id: 1, name: "Sagar", age: 25 },
    { id: 2, name: "Rahul", age: 27 }
  ];

  return (
    <>
      <header>
        <h1>React Basics</h1>
      </header>

      <main>
        <section>
          <h2>Counter: {count}</h2>

          <button onClick={() => setCount(prev => prev + 1)}>
            Increment
          </button>
        </section>

        <section>
          {users.map(user => (
            <UserCard
              key={user.id}
              name={user.name}
              age={user.age}
            />
          ))}
        </section>

        {count > 5 && (
          <p>Counter is greater than 5.</p>
        )}
      </main>
    </>
  );
}

export default App;
```

# 49. Must-Remember Interview Answers

### What is React?

> React is a JavaScript library for building component-based user interfaces using a declarative programming model.

### What is JSX?

> JSX is a JavaScript syntax extension that allows us to describe UI using markup-like syntax.

### What are props?

> Props are read-only inputs passed from a parent component to a child component.

### What is state?

> State is data managed by a component that can change over time and cause the component to render again.

### What is a Fragment?

> A Fragment lets React group multiple elements without adding an extra DOM element.

### What is reconciliation?

> Reconciliation is React's process of determining how the rendered UI has changed and what updates need to be committed.

### What is Fiber?

> Fiber is React's internal architecture for representing and scheduling rendering work.

### Why are keys required in lists?

> Keys provide stable identity for list items so React can correctly track items when a list changes.

### What is lifting state up?

> Moving shared state to the nearest common parent so multiple child components can use the same source of truth.

### What is one-way data flow?

> Data normally flows from parent to child through props. A child can request changes by calling a callback supplied by its parent.
