# 5. Redux Toolkit

Redux is a predictable state-management library for JavaScript applications. **Redux Toolkit (RTK)** is the official recommended way to write Redux logic because it reduces boilerplate and provides good defaults.

---

## 1. Why Redux?

React state is excellent for local component state, but some state may need to be shared across many unrelated components.

Examples:

* Logged-in user
* Authentication status
* Shopping cart
* Notifications
* Application preferences
* Complex multi-step state
* Cached server data

Without a centralized approach, this can lead to extensive prop drilling and complicated state synchronization.

Redux provides a centralized store and predictable state transitions.

### Redux data flow

```text
UI
 ↓
dispatch(action)
 ↓
middleware
 ↓
reducer
 ↓
Redux store
 ↓
selector
 ↓
UI re-renders
```

Redux follows a **one-way data flow**.

---

# 2. Redux Core Concepts

There are several important Redux terms:

| Concept        | Meaning                                                |
| -------------- | ------------------------------------------------------ |
| Store          | Holds the application's Redux state                    |
| State          | Data currently stored in Redux                         |
| Action         | Describes what happened                                |
| Action creator | Function that creates an action                        |
| Reducer        | Calculates the next state                              |
| Dispatch       | Sends an action to the store                           |
| Selector       | Reads data from the store                              |
| Middleware     | Intercepts dispatched actions                          |
| Slice          | A feature's Redux state + reducers + generated actions |

A useful mental model:

```text
Action
  ↓
Reducer
  ↓
New State
  ↓
Store
```

# 4. Store

The Redux store contains the application's Redux state.

With Redux Toolkit, create the store using `configureStore()`.

```js
// src/app/store.js

import { configureStore } from "@reduxjs/toolkit";
import todoReducer from "../features/todos/todosSlice";

export const store = configureStore({
  reducer: {
    todos: todoReducer,
  },
});
```

The `reducer` object maps Redux state keys to reducers.

Therefore the state shape is:

```js
{
  todos: [...]
}
```

So:

```js
state.todos
```

contains the state managed by `todoReducer`.

---

# 5. Why `configureStore()`?

`configureStore()` is preferred over manually calling the old Redux `createStore()` API.

It provides useful defaults such as:

* Redux DevTools integration
* Middleware setup
* Thunk middleware
* Development checks
* Better configuration defaults

Example:

```js
const store = configureStore({
  reducer: {
    users: userReducer,
    todos: todoReducer,
  },
});
```

# 6. Slice

A **slice** represents one feature's Redux state and the reducers that update it.

RTK provides:

```js
createSlice()
```

Example:

```js
// src/features/todos/todosSlice.js

import { createSlice, nanoid } from "@reduxjs/toolkit";

const initialState = [];

const todosSlice = createSlice({
  name: "todos",
  initialState,
  reducers: {
    addTodo: {
      reducer(state, action) {
        state.push(action.payload);
      },

      prepare(text) {
        return {
          payload: {
            id: nanoid(),
            text,
            completed: false,
          },
        };
      },
    },

    toggleTodo(state, action) {
      const todo = state.find(
        (todo) => todo.id === action.payload
      );

      if (todo) {
        todo.completed = !todo.completed;
      }
    },

    removeTodo(state, action) {
      return state.filter(
        (todo) => todo.id !== action.payload
      );
    },
  },
});

export const {
  addTodo,
  toggleTodo,
  removeTodo,
} = todosSlice.actions;

export default todosSlice.reducer;
```

# 7. What Does `createSlice()` Generate?

Given:

```js
const todosSlice = createSlice({
  name: "todos",
  initialState: [],
  reducers: {
    addTodo(state, action) {
      state.push(action.payload);
    },
  },
});
```

Redux Toolkit generates:

### Action creator

```js
todosSlice.actions.addTodo
```

### Reducer

```js
todosSlice.reducer
```

Therefore:

```js
export const { addTodo } = todosSlice.actions;
export default todosSlice.reducer;
```

# 8. Reducer

A reducer determines how state changes in response to an action.

Conceptually:

```js
(previousState, action) => nextState
```

Example:

```js
function counterReducer(state, action) {
  switch (action.type) {
    case "counter/increment":
      return state + 1;

    default:
      return state;
  }
}
```

Reducers should be:

* Predictable
* Deterministic
* Free from side effects
* Based on current state and action

---

# 9. Immer and "Mutating" Redux State

One of the most important Redux Toolkit interview topics is this:

```js
state.push(action.payload);
```

Normally, directly mutating Redux state would be incorrect.

However, Redux Toolkit uses **Immer** internally.

Therefore this is valid inside an RTK reducer:

```js
addTodo(state, action) {
  state.push(action.payload);
}
```

Immer tracks the apparent mutation and produces an immutable next state.

You can also return a new state:

```js
removeTodo(state, action) {
  return state.filter(
    (todo) => todo.id !== action.payload
  );
}
```

Both styles are valid in RTK reducers.

### Important

This does **not** mean Redux state can be mutated anywhere.

The Immer mutation syntax is supported inside Redux Toolkit's Immer-powered reducers.

# 10. Action

An action describes something that happened.

Example:

```js
{
  type: "todos/toggleTodo",
  payload: "123"
}
```

With Redux Toolkit, you usually don't manually create these objects.

Instead:

```js
dispatch(toggleTodo("123"));
```

The generated action creator creates the action.

# 11. Dispatch

`dispatch()` sends an action to Redux.

```js
const dispatch = useDispatch();

dispatch(addTodo("Learn Redux"));
```

The action then goes through Redux middleware and eventually reaches the reducer.

# 12. `useDispatch()`

`useDispatch()` gives access to the Redux store's `dispatch` function.

```jsx
import { useDispatch } from "react-redux";
import { toggleTodo } from "./todosSlice";

function TodoItem({ todo }) {
  const dispatch = useDispatch();

  return (
    <button
      onClick={() => dispatch(toggleTodo(todo.id))}
    >
      Toggle
    </button>
  );
}

export default TodoItem;
```

# 13. `useSelector()`

`useSelector()` reads data from the Redux store.

```jsx
import { useSelector } from "react-redux";

function TodoList() {
  const todos = useSelector((state) => state.todos);

  return (
    <ul>
      {todos.map((todo) => (
        <li key={todo.id}>
          {todo.text}
        </li>
      ))}
    </ul>
  );
}

export default TodoList;
```

If the store is:

```js
{
  todos: [...]
}
```

then:

```js
useSelector((state) => state.todos);
```

returns the todo array.

---

# 14. `useSelector()` and Re-rendering

React-Redux subscribes components to the Redux store.

When an action is dispatched:

1. Redux updates the store.
2. Selectors are evaluated.
3. React-Redux compares the selected result.
4. The component re-renders if the selected value changed according to the selector's equality behavior.

By default, `useSelector()` uses strict reference equality (`===`) for the selected result.

Therefore this can cause unnecessary updates:

```js
const data = useSelector((state) => ({
  todos: state.todos,
  user: state.user,
}));
```

The selector creates a new object each time.

Better options include:

```js
const todos = useSelector((state) => state.todos);
const user = useSelector((state) => state.user);
```

or using memoized selectors when appropriate.

---

# 15. Provider

React components need access to the Redux store.

Use:

```jsx
import { Provider } from "react-redux";
import { store } from "./app/store";

root.render(
  <Provider store={store}>
    <App />
  </Provider>
);
```

Complete example:

```jsx
// src/main.jsx

import React from "react";
import ReactDOM from "react-dom/client";
import { Provider } from "react-redux";
import { store } from "./app/store";
import App from "./App";

ReactDOM.createRoot(
  document.getElementById("root")
).render(
  <React.StrictMode>
    <Provider store={store}>
      <App />
    </Provider>
  </React.StrictMode>
);
```

Without the `Provider`, hooks such as:

```js
useSelector()
useDispatch()
```

cannot access the Redux store.

## Add Todo

```jsx
// src/components/AddTodo.jsx

import { useState } from "react";
import { useDispatch } from "react-redux";
import { addTodo } from "../features/todos/todosSlice";

function AddTodo() {
  const [text, setText] = useState("");
  const dispatch = useDispatch();

  function handleSubmit(event) {
    event.preventDefault();

    const trimmedText = text.trim();

    if (!trimmedText) {
      return;
    }

    dispatch(addTodo(trimmedText));
    setText("");
  }

  return (
    <form onSubmit={handleSubmit}>
      <input
        value={text}
        onChange={(event) => setText(event.target.value)}
        placeholder="Enter todo"
      />

      <button type="submit">
        Add
      </button>
    </form>
  );
}

export default AddTodo;
```

## Todo List

```jsx
// src/components/TodoList.jsx

import { useDispatch, useSelector } from "react-redux";
import {
  removeTodo,
  toggleTodo,
} from "../features/todos/todosSlice";

function TodoList() {
  const todos = useSelector((state) => state.todos);
  const dispatch = useDispatch();

  if (todos.length === 0) {
    return <p>No todos yet.</p>;
  }

  return (
    <ul>
      {todos.map((todo) => (
        <li key={todo.id}>
          <label>
            <input
              type="checkbox"
              checked={todo.completed}
              onChange={() => dispatch(toggleTodo(todo.id))}
            />

            {todo.text}
          </label>

          <button
            type="button"
            onClick={() => dispatch(removeTodo(todo.id))}
          >
            Delete
          </button>
        </li>
      ))}
    </ul>
  );
}

export default TodoList;
```

# 19. Selectors

A selector is a function that reads or derives data from Redux state.

Simple selector:

```js
const selectTodos = (state) => state.todos;
```

Usage:

```js
const todos = useSelector(selectTodos);
```

Selectors are useful because they centralize knowledge about the state shape.

Example:

```js
const selectCompletedTodos = (state) =>
  state.todos.filter((todo) => todo.completed);
```

Then:

```js
const completedTodos = useSelector(selectCompletedTodos);
```

---

# 20. Memoized Selectors

If a selector performs expensive calculations, memoization can prevent unnecessary recalculation.

Redux Toolkit exports `createSelector` through Reselect:

```js
import { createSelector } from "@reduxjs/toolkit";

const selectTodos = (state) => state.todos;

export const selectCompletedTodos = createSelector(
  [selectTodos],
  (todos) =>
    todos.filter((todo) => todo.completed)
);
```

Now the derived result is memoized based on its input selectors.

# 21. Redux Middleware

Middleware sits between `dispatch()` and the reducer.

```text
dispatch(action)
       ↓
   middleware
       ↓
    reducer
       ↓
     store
```

Middleware can be used for:

* Logging
* Async workflows
* Analytics
* Error reporting
* Side effects
* Action transformation

Example:

```js
const loggerMiddleware = (store) => (next) => (action) => {
  console.log("Dispatching:", action);

  const result = next(action);

  console.log("New state:", store.getState());

  return result;
};
```

Configure it with Redux Toolkit:

```js
import { configureStore } from "@reduxjs/toolkit";

export const store = configureStore({
  reducer: {
    todos: todoReducer,
  },

  middleware: (getDefaultMiddleware) =>
    getDefaultMiddleware().concat(loggerMiddleware),
});
```

Be careful when replacing the default middleware rather than extending it, because you may accidentally remove useful defaults.

---

# 22. Redux Thunk

Redux Toolkit's default middleware includes thunk support.

A thunk allows dispatching a function instead of only a plain action object.

For example:

```js
dispatch(fetchTodos());
```

The thunk can perform asynchronous work and then dispatch actions.

However, for modern Redux applications, you generally don't need to write manual thunks for every server-data use case.

---

# 23. `createAsyncThunk`

Redux Toolkit provides:

```js
createAsyncThunk()
```

for common async workflows.

Example:

```js
import {
  createAsyncThunk,
  createSlice,
} from "@reduxjs/toolkit";

export const fetchTodos = createAsyncThunk(
  "todos/fetchTodos",
  async () => {
    const response = await fetch(
      "https://example.com/api/todos"
    );

    if (!response.ok) {
      throw new Error("Failed to fetch todos");
    }

    return response.json();
  }
);
```

Then handle its lifecycle actions:

```js
const todosSlice = createSlice({
  name: "todos",

  initialState: {
    items: [],
    status: "idle",
    error: null,
  },

  reducers: {},

  extraReducers: (builder) => {
    builder
      .addCase(fetchTodos.pending, (state) => {
        state.status = "loading";
        state.error = null;
      })

      .addCase(fetchTodos.fulfilled, (state, action) => {
        state.status = "succeeded";
        state.items = action.payload;
      })

      .addCase(fetchTodos.rejected, (state, action) => {
        state.status = "failed";
        state.error =
          action.error.message ?? "Request failed";
      });
  },
});
```

`createAsyncThunk()` generates lifecycle actions:

```text
pending
fulfilled
rejected
```

# 24. `extraReducers`

`reducers` defines reducers for actions owned by the slice.

```js
reducers: {
  addTodo(state, action) {
    // ...
  },
}
```

`extraReducers` allows a slice to respond to actions defined elsewhere.

For example:

```js
extraReducers: (builder) => {
  builder.addCase(fetchTodos.fulfilled, (state, action) => {
    state.items = action.payload;
  });
}
```

This is commonly used with `createAsyncThunk()`.

# 25. RTK Query

Redux Toolkit also includes **RTK Query**, a data-fetching and caching solution.

RTK Query can handle:

* API requests
* Caching
* Loading states
* Error states
* Cache invalidation
* Refetching
* Request deduplication
* Generated React hooks

For server data, RTK Query is often preferable to manually creating:

```text
loading
success
error
fetch thunk
reducers
cache logic
```

for every endpoint.

Example:

```js
import { createApi, fetchBaseQuery } from "@reduxjs/toolkit/query/react";

export const api = createApi({
  reducerPath: "api",

  baseQuery: fetchBaseQuery({
    baseUrl: "https://example.com/api",
  }),

  endpoints: (builder) => ({
    getTodos: builder.query({
      query: () => "/todos",
    }),
  }),
});

export const { useGetTodosQuery } = api;
```

Then:

```jsx
function TodoList() {
  const {
    data: todos = [],
    isLoading,
    isError,
  } = useGetTodosQuery();

  if (isLoading) {
    return <p>Loading...</p>;
  }

  if (isError) {
    return <p>Failed to load todos.</p>;
  }

  return (
    <ul>
      {todos.map((todo) => (
        <li key={todo.id}>
          {todo.title}
        </li>
      ))}
    </ul>
  );
}
```

RTK Query itself needs to be added to the store:

```js
import { configureStore } from "@reduxjs/toolkit";
import { api } from "../services/api";

export const store = configureStore({
  reducer: {
    [api.reducerPath]: api.reducer,
  },

  middleware: (getDefaultMiddleware) =>
    getDefaultMiddleware().concat(api.middleware),
});
```

# 26. Redux vs React Context

| Redux                           | Context                                  |
| ------------------------------- | ---------------------------------------- |
| Full state-management ecosystem | Value propagation mechanism              |
| Centralized store               | Provider-based values                    |
| Actions and reducers            | No required reducer/action model         |
| Middleware available            | No built-in middleware system            |
| DevTools support                | No Redux DevTools                        |
| Selectors                       | `useContext` reads context value         |
| Good for complex global state   | Good for relatively stable shared values |
| RTK Query available             | No built-in data-fetching/cache solution |

Context and Redux are not mutually exclusive.

An application can use:

```text
React local state
+
Context
+
Redux
+
Server-state library
```

depending on the problem.

---

# 27. Redux vs Local State

Use local React state when state belongs to one component or a small component subtree.

```js
const [isOpen, setIsOpen] = useState(false);
```

Redux can be useful when:

* Many distant components need the same state.
* State transitions are complex.
* Multiple features depend on the same state.
* Debugging state transitions centrally is valuable.
* Middleware or Redux DevTools provide useful benefits.

Do not put every piece of state into Redux.

For example, this usually doesn't need Redux:

```js
const [inputValue, setInputValue] = useState("");
```

---

# 28. Redux State Should Usually Be Serializable

Redux works best when actions and state contain serializable values.

Prefer:

```js
{
  id: 1,
  name: "John",
  createdAt: "2026-01-01T00:00:00.000Z"
}
```

rather than storing things such as:

```js
Date
Map
Set
Promise
Function
DOM node
class instance
```

There are legitimate exceptions, but non-serializable values can interfere with:

* Debugging
* Persistence
* DevTools
* Time-travel debugging
* Predictability

Redux Toolkit's development middleware helps detect common non-serializable values.

# 30. Single Redux Store

The standard Redux architecture generally uses one store for the application.

Multiple feature reducers are combined into that store:

```js
configureStore({
  reducer: {
    auth: authReducer,
    cart: cartReducer,
    todos: todoReducer,
  },
});
```

This is different from saying every feature needs its own Redux store.

Usually, you create one application store and organize state into slices.

# 31. Redux Toolkit vs Old Redux

### Old Redux style

You commonly had to write:

```js
const ADD_TODO = "ADD_TODO";

function addTodo(todo) {
  return {
    type: ADD_TODO,
    payload: todo,
  };
}

function reducer(state = [], action) {
  switch (action.type) {
    case ADD_TODO:
      return [...state, action.payload];

    default:
      return state;
  }
}
```

RTK simplifies this:

```js
const todosSlice = createSlice({
  name: "todos",

  initialState: [],

  reducers: {
    addTodo(state, action) {
      state.push(action.payload);
    },
  },
});
```

RTK reduces boilerplate while retaining Redux's predictable architecture.

# 32. Common Redux Mistakes

### ❌ Incorrect package name

```bash
npm install @reduxjs/tookit
```

### ✅ Correct

```bash
npm install @reduxjs/toolkit react-redux
```

---

### ❌ Forgetting the Provider

```jsx
<App />
```

while using:

```js
useSelector(...)
```

### ✅

```jsx
<Provider store={store}>
  <App />
</Provider>
```

---

### ❌ Wrong selector

If the store is:

```js
configureStore({
  reducer: {
    todos: todoReducer,
  },
});
```

then:

```js
useSelector((state) => state.todo);
```

is incorrect if the key is `todos`.

### ✅

```js
useSelector((state) => state.todos);
```

---

### ❌ Mutating Redux state outside Immer reducers

```js
const todos = store.getState().todos;

todos.push(newTodo);
```

Do not do this.

### ✅

Dispatch an action:

```js
dispatch(addTodo(newTodo));
```

---

### ❌ Putting every state value into Redux

```js
const [input, setInput] = useState("");
```

is usually better than putting a temporary input value into Redux.

---

### ❌ Treating Redux as a replacement for all React state

Redux and React local state solve different problems.

# 33. Redux Interview Questions

## Q: What is Redux?

Redux is a predictable state-management library based on a centralized store, dispatched actions, and reducers that calculate state transitions.

---

## Q: What is Redux Toolkit?

Redux Toolkit is the official recommended way to write Redux logic. It provides APIs such as:

```js
configureStore
createSlice
createAsyncThunk
createSelector
```

and also includes RTK Query.

---

## Q: What is a Redux store?

The store holds the application's Redux state and provides APIs for dispatching actions and subscribing to state changes.

---

## Q: What is a reducer?

A reducer calculates the next state based on the current state and an action.

```js
(state, action) => nextState
```

---

## Q: What is an action?

An action is an object describing something that happened.

Example:

```js
{
  type: "todos/addTodo",
  payload: {
    id: 1,
    text: "Learn Redux",
  },
}
```

---

## Q: What is dispatch?

`dispatch()` sends an action to the Redux store.

```js
dispatch(addTodo("Learn Redux"));
```

---

## Q: What is a selector?

A selector is a function that reads or derives data from Redux state.

```js
const selectTodos = (state) => state.todos;
```

---

## Q: Why can Redux Toolkit reducers use mutation syntax?

Redux Toolkit uses Immer internally.

```js
state.push(item);
```

is converted into an immutable state update by Immer.

---

## Q: What is middleware?

Middleware intercepts dispatched actions before they reach reducers.

It is commonly used for:

* Async logic
* Logging
* Analytics
* Side effects
* Error handling

---

## Q: What is `createAsyncThunk()`?

It is a Redux Toolkit utility for handling common asynchronous workflows and generating:

```text
pending
fulfilled
rejected
```

actions.

---

## Q: Should API data always be stored in Redux?

No.

For server data, RTK Query is often a better fit because it provides fetching, caching, invalidation, and related server-state behavior.

---

## Q: Redux vs Context?

Context primarily provides values to a component subtree.

Redux provides a broader state-management architecture with:

* Centralized state
* Actions
* Reducers
* Middleware
* Selectors
* DevTools
* RTK Query

# 36. Interview One-Liners

### Redux

> Redux is a predictable state-management library with centralized state and explicit state transitions.

### Redux Toolkit

> Redux Toolkit is the official recommended approach for writing Redux logic with less boilerplate and better defaults.

### Slice

> A slice groups a feature's state, reducers, and generated action creators.

### `useSelector`

> `useSelector` reads a selected value from the Redux store and subscribes the component to relevant store updates.

### `useDispatch`

> `useDispatch` provides the Redux store's dispatch function so components can dispatch actions.

### Middleware

> Middleware sits between dispatch and reducers and is commonly used for async workflows and side effects.

### Immer

> Redux Toolkit uses Immer so reducers can use mutation-like syntax while producing immutable state updates.

### RTK Query

> RTK Query is Redux Toolkit's data-fetching and caching solution for server state.
